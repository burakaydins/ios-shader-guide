## 1. Coordinate transforms

Most interesting patterns come from warping space and drawing a single simple shape.

{{code:coordHelpers}}

- **Centering and ratio:** `centeredUV(position, size)` (`ShaderHelpers.h`) makes the center (0,0) and puts the height at −0.5…0.5; circles stay circles.
- **Repetition:** `tileLocal` divides space into cells; draw the same shape in each cell. The cell index is `floor(p / cell)`; apply `hash21` to it and you get a random value per cell.
- **Mirror:** `abs(p)` folds an axis; for a kaleidoscope see example 2 in `shadertoy-to-msl.md` (folding the angle with `mod`).
- **Rotation:** `rotate2d(p, a)` (`ShaderHelpers.h`). Tie the rotation to `time` for animation.

## 2. SDF library and operations

SDF (signed distance function): the distance from a point to a shape, negative inside. You combine shapes by doing arithmetic on their distances.

{{code:sdfOps}}

| Want | Operation |
|---|---|
| Union | `min(a, b)` or the soft form `smin(a, b, k)` (blob/metaball effect) |
| Intersection | `max(a, b)` |
| Subtraction (a − b) | `max(a, -b)` |
| Hollow out (outline) | `abs(d) - thickness` |
| Thicken / round | `d - r` |

To draw a shape, turn the distance into a coverage: `fillAA(d, aa)` (fill) and `strokeAA(d, w, aa)` (line).

## 3. Anti-aliasing

Hard `step` edges look jagged. Soften the edge to about one pixel width with `smoothstep(-aa, aa, d)`. `aa` must be in the **same unit** as `d`:

- If `d` is in points (e.g. `position - center`): `aa ≈ 0.75` (about 1.5 points in total).
- If `d` is in uv units divided by `size.y`: `aa = 1.5 / size.y`.

`position` is in points; on a Retina screen a point is 2–3 physical pixels, so these values are visually sufficient. This analytic approach is recommended instead of a derivative-based method (`fwidth`) (whether derivative functions can be used inside a stitchable shader was not verified).

## 4. UI pieces with SDFs

Drawing small UI pieces with a shader gives scale-independent sharpness in a single pass.

**Dot grid** (a background pattern):

{{code:dotGrid}}

```swift
Rectangle().fill(.black)
    .colorEffect(ShaderLibrary.dotGrid(.float(24), .float(2.5), .color(.white.opacity(0.35))))
```

`spacing` and `radius` are in points, `dotColor` is a premultiplied color.

**Progress ring** (fills clockwise from 12 o'clock):

{{code:progressRing}}

```swift
Rectangle().fill(.black)
    .frame(width: 120, height: 120)
    .colorEffect(ShaderLibrary.progressRing(.float2(120, 120), .float(progress), .float(10),
                                            .color(.white.opacity(0.15)), .color(.green)))
```

Here the background is the base view's color (`Rectangle().fill(.black)` → black). Whether the shader is called on a fully transparent base (`Color.clear`) was not verified; if you need a transparent background, compile and try, and if it does not work use a semi-transparent base. To drive `progress` with `withAnimation`, use an `Animatable` ViewModifier (`swift-patterns.md` section 6). There are no rounded caps; adding them needs a union with an `sdCircle` at the end angle.

The same method makes rounded-corner badges, dividers, pills (`sdRoundBox`) and segment lines (`sdSegment`). If SwiftUI's own shapes are enough, use them; a shader adds value when you need a pattern or animation.

## 5. Breaking banding with dither

In soft gradients, 8-bit color steps can make visible bands. Solutions:

- If you use the shader as a `ShapeStyle`, turn on the `Shader.dithersColor` property (`swiftui-shaders.md` section 10).
- Your own solution: add a very small noise, different for each pixel, to the output.

{{code:ign}}

```metal
float3 col = palette(t);
col += (ign(position) - 0.5f) / 255.0f;       // ±0.5 color step
return half4(half3(col), 1.0h);
```

## 6. Raymarching: growing the scene

`recipes.md` recipe 13 draws a single sphere. Whatever the scene, the method is the same: advance from the ray origin, at each step measure the distance to the scene (`d`), advance that much, and when `d` gets small enough you have hit. The normal comes from the gradient of the distance (the difference of neighboring samples). For a richer scene use this in place of `sceneSDF`:

{{code:raymarchScene}}

Three settings drive the cost: the step count (48 is reasonable to start), the maximum distance (8) and the hit threshold (0.002). Watch out for:

- Keep the loop constant and small; an early `break` helps on average, but the worst pixel (where the ray grazes the scene) still spends all the steps.
- Each `sceneSDF` call runs 6 more times in the normal computation; if the scene is expensive, compute the normal with the 4-sample (tetrahedron) method.
- Measure full screen on a real device; it is often more suitable to use it on a small area (e.g. a 300×300 card).
- Additions such as soft shadows and ambient occlusion quickly raise the cost; start on them by lowering the step budget.

## 7. The noise family

| Kind | Where | Note |
|---|---|---|
| `valueNoise` | General purpose, cheap | The grid pattern can show |
| `fbm` | Cloud, smoke, marble, terrain | Octave count = cost |
| `voronoi` | Cells, cracks, underwater light | Scans 9 cells |
| Domain warping | Fluid, aurora | `fbm(p + fbm(p + t))`; see `recipes.md` recipe 2 |
| Ridged | Mountain ridge, lightning | A transform of the form `1.0 - abs(2.0 * n - 1.0)` |
| Turbulence | Fire, swirling flow | A sum of `abs(2.0 * n - 1.0)` |

Keep the noise space independent of the screen by dividing by `size.y`. Add time to the noise's **input** (`fbm(p + t)`), not its output.

## 8. Time and curves

- Looping animation: `0.5 + 0.5 * sin(t)`. Ping-pong: `pingPong(t)` (section 1).
- Soft start/end: `smoothstep(0, 1, t)`; for harder curves take a power: `pow(t, 3.0)`.
- For one-shot animations drive time with a SwiftUI animation (`animatableData`, see `swift-patterns.md` section 6); for continuous animations use `TimelineView`.
- To animate noise, scroll it through space (`p + float2(0, t)`); keep `t` slow (0.05–0.3), as fast looks jittery.

## 9. Notes on color

- `Shader.Argument.color` and the `color` arriving in `colorEffect` are premultiplied colors in the destination color space (Apple's documentation). The color returned from the shader must also be premultiplied in the destination color space.
- The cosine palette (`palette`) gives continuous color from one formula; if you need design control, blend between two or three fixed colors with `mix`.
- Pass the app's design colors to the shader with `.color(...)`; do not embed them in the shader.
- When the difference between linear and gamma space starts to matter in this context is not documented; if blending results come out darker/lighter than expected, suggest the user compare by experiment.

## 10. The limit of SwiftUI shaders: when to use `MTKView`

SwiftUI shader modifiers are not enough in these cases:

- Multi-pass work (Shadertoy Buffer A–D, a blur pipeline, bloom).
- Reading the previous frame (feedback, trails, fluid simulation).
- Compute shaders (particle systems, simulation).
- Your own vertex data (a 3D model, a mesh).
- Many draw calls per frame.

For these use `MTKView` + `MTLRenderPipelineState` (and `MTLComputePipelineState` if needed), embedded in SwiftUI with `UIViewRepresentable`. This skill does not cover that path in detail; tell the user when they reach this point and point them to Apple's Metal sample code. If you just want a simple two-pass effect, a two-layer SwiftUI view (a background effect + a second effect on top) is often enough.
