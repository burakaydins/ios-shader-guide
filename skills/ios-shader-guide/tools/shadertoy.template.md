## 1. License and portability first

**License.** If a Shadertoy shader's header does not state a license, the default is generally CC BY-NC-SA 3.0: no commercial use, attribution required, share-alike required. If the app is commercial or closed-source, copying and converting the code may violate this license. Options: ask the author, pick a shader with a free license (CC0, MIT, etc.), or rewrite the idea and technique in your own code (the technique is free, the code itself is not). Do not give a legal opinion; just warn.

**Portability.**

| Shadertoy feature | Status |
|---|---|
| A single `mainImage`, `iTime`, `iResolution` | Ports |
| `iMouse` | Ports: pass the touch point as a uniform |
| Image/texture via `iChannel` | Ports, but a Shader can have only **one** `.image` argument |
| Reading the screen itself (post-process) | With `layerEffect` |
| **Buffer A–D** (multipass) | Does not port: needs `MTKView` + an offscreen texture |
| Reading the previous frame (`iFrame`, feedback) | Does not port, same reason |
| Audio, microphone, video, cube map | Does not port |
| Very heavy raymarching (100+ steps, full screen) | Ports but may be slow on device; reduce steps, shrink the area |

If it will not port, say so at the start; suggest the `MTKView` route to the user or offer to write a single-pass approximation of the effect.

## 2. Translation table

| GLSL | MSL |
|---|---|
| `vec2/3/4` | `float2/3/4` |
| `ivec2` / `uvec2` / `bvec2` | `int2` / `uint2` / `bool2` |
| `mat2/3/4` | `float2x2` / `float3x3` / `float4x4` |
| `mod(x, y)` | `x - y * floor(x / y)` (helper `glslMod`). `fmod` gives a different result for negative x |
| `atan(y, x)` (two arguments) | `atan2(y, x)` |
| `atan(x)` (one argument) | `atan(x)` |
| `inversesqrt(x)` | `rsqrt(x)` |
| `texture(iChannel0, uv)` | `tex.sample(s, uv)` (`constexpr sampler s(address::repeat, filter::linear);`) |
| `texelFetch(tex, ivec2, 0)` | `tex.read(uint2(...))` |
| `textureSize(tex, 0)` | `float2(tex.get_width(), tex.get_height())` |
| `dFdx`, `dFdy`, `fwidth` | The MSL names are `dfdx`, `dfdy`, `fwidth`; whether they can be used inside a stitchable shader was not verified. Do not use them; write analytic anti-aliasing (`aa = 1.5 / size.y`) |
| `discard` | Return alpha 0 (`discard_fragment()` is specific to fragment functions; do not use it in a SwiftUI shader) |
| `precision mediump float;`, `highp`, `lowp` | Delete |
| `in` parameter | Plain parameter |
| `out` / `inout` parameter | `thread float&`, `thread float3&` |
| Written global variable | None. Pass as a parameter or make it local |
| Global constant `const float PI = 3.14;` | `constant float kPi = 3.14159265f;` (at global scope `constant` is required) |
| Array `float a[3] = float[3](...)` | `float a[3] = {...};`; for a global, `constant float a[3] = {...};` |
| Recursion | Forbidden in MSL; turn it into a loop |
| Matrix constructor `mat2(a,b,c,d)` | `float2x2(float2(a, b), float2(c, d))`, column-major like GLSL |
| `v.xyx`, `v.rgb` | Same |
| `float x = 1;` (int → float) | Works but write it explicitly: `1.0f` |
| `a % b` (int) | Same |
| `mix`, `fract`, `clamp`, `step`, `smoothstep`, `length`, `dot`, `cross`, `normalize`, `reflect`, `pow`, `exp`, `sin`... | Same |
| `smoothstep(e0, e1, x)` with `e0 > e1` | Undefined: write `1.0 - smoothstep(e1, e0, x)`. Common in Shadertoy code; seems to "work" on some GPUs |
| `#define` | Same (preprocessor) |

Helpers:

```metal
static inline float  glslMod(float x, float y)   { return x - y * floor(x / y); }
static inline float2 glslMod(float2 x, float2 y) { return x - y * floor(x / y); }
```

Literal forms: in MSL `1.0` and `1.0f` are `float`, `1.0h` is `half`; there is no `double`.

## 3. Equivalents of Shadertoy variables

| Shadertoy | SwiftUI/MSL |
|---|---|
| `fragCoord` | `float2(position.x, size.y - position.y)` (**y flipped**, origin bottom-left) |
| `iResolution.xy` | `size` (from Swift, `.float2(proxy.size)`) |
| `iTime` | `time` (from Swift, seconds since the start) |
| `iMouse.xy` | `touch` (from Swift, `.float2(point)`, flip y the same way) |
| `iChannel0..3` | `texture2d<half>` (at most one `.image` per shader) |
| `fragColor` | the function's return value: `half4(half3(col), 1.0h)` |
| `iDate`, `iFrame`, `iTimeDelta`, `iChannelTime` | Usually not needed; pass as uniforms if required |

**Points are not pixels.** `position` and `size` are in points. If the original code uses pixel constants such as "a 2-pixel line", multiply by `@Environment(\.displayScale)` and pass it as an argument.

## 4. Y axis: flip it in one place

In Shadertoy the origin is bottom-left; in SwiftUI it is top-left. If not flipped, the effect comes out upside down. Do the flip **in one place**, at the entry point (`fragCoord = float2(position.x, size.y - position.y)`); do not touch the rest of the shader. Apply the same flip to the touch point (`iMouse`). If you read a texture and the image comes out inverted, also flip the texture coordinate's `y` (`1.0 - uv.y`); which one is needed depends on how the texture was loaded, so decide by looking at the output.

## 6. Example 1: Shadertoy's default shader

Shadertoy's new-shader template (a short and common starting example):

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec3 col = 0.5 + 0.5 * cos(iTime + uv.xyx + vec3(0, 2, 4));
    fragColor = vec4(col, 1.0);
}
```

```swift
AnimatedShader { t in
    Rectangle()
        .visualEffect { c, proxy in
            c.colorEffect(ShaderLibrary.shadertoyDefault(.float2(proxy.size), .float(t)))
        }
}
```

What changed: `mainImage` → a `[[ stitchable ]]` function, `fragColor` → return value, `iResolution.xy` → `size`, `iTime` → `time`, `vec3` → `float3`, an `f` suffix on literals, y flipped.

## 7. Example 2: functions, `inout`, `mod`, `atan`

A GLSL kaleidoscope written for this guide (with no third-party license):

```glsl
const float PI = 3.14159265;

float ring(vec2 p, float r, float w) {
    return smoothstep(w, 0.0, abs(length(p) - r));
}

void fold(inout vec2 p, float n) {
    float a = atan(p.y, p.x);
    float seg = 2.0 * PI / n;
    a = mod(a + seg * 0.5, seg) - seg * 0.5;
    p = length(p) * vec2(cos(a), sin(a));
}

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 p = (fragCoord - 0.5 * iResolution.xy) / iResolution.y;
    fold(p, 6.0);
    p -= vec2(0.25, 0.0);
    float v = ring(p, 0.12 + 0.03 * sin(iTime), 0.02);
    vec3 col = 0.5 + 0.5 * cos(iTime + p.xyx * 6.0 + vec3(0, 2, 4));
    fragColor = vec4(col * v, 1.0);
}
```

{{code:kaleido}}

Changes made, line by line:

1. `const float PI` → `constant float kPi` (a global constant needs `constant`).
2. `mod` → `glslMod` (with negative angles `fmod` falls into the wrong segment).
3. `atan(y, x)` → `atan2(y, x)`.
4. `inout vec2 p` → `thread float2& p`.
5. `smoothstep(w, 0.0, x)` had reversed edges; it became `1.0 - smoothstep(0.0, w, x)`.
6. `fragCoord` was computed with y flipped at the entry point; the rest stayed the same.
7. An `f` suffix was added to every literal.

## 8. Textures, mouse and audio

- **Texture (`iChannel0`).** On the Swift side `.image(Image("noise"))`, in MSL a `texture2d<half> tex` parameter. At most one image is supported per shader; if you need a second noise, generate it inside the shader with `valueNoise`/`hash21` from `ShaderHelpers.h`. Sampler: `constexpr sampler s(address::repeat, filter::linear);`.
- **Mouse (`iMouse`).** Get the touch point with `DragGesture`, pass it as `.float2(point)`, flip y with `size.y - touch.y`. There is no equivalent of Shadertoy's `iMouse.zw` (click state); if needed pass a separate `float` flag argument.
- **Audio/microphone (`iChannel` audio input).** Does not port. You can do the audio analysis in Swift and give the shader a few `float`s (bass, treble level); it is not a one-to-one match for Shadertoy's FFT texture.

## 9. Post-conversion checklist

- [ ] Was the y axis flipped once at the entry point? (if the effect is upside down it was forgotten)
- [ ] Is `time` relative to the start on the Swift side?
- [ ] Were all `vec` / `mod` / `atan` conversions done?
- [ ] Is there any written global variable left? (there cannot be)
- [ ] Were `smoothstep` calls with reversed edges fixed?
- [ ] Are loop bounds constant and reasonable? (big constant loops lengthen compile and run)
- [ ] Alpha: should the result be opaque in `colorEffect`, or should `color.a` be preserved?
- [ ] Were pixel-based constants multiplied by `displayScale`?
- [ ] Were the license and attribution header added? (section 10)
- [ ] Did you list for the user what you changed from the original?
- [ ] If you could not compile, did you say "it needs to be compiled in Xcode"?
